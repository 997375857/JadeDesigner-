# e5.95 IDA 静态分析记录（2026-08-30）

目标：`%E_LANG_HOME%\e5.95.exe`

分析方式：IDA Pro 9.3 MCP，使用副本离线分析；未修改原始 e5.95。

## 关键结论

### 1. FN_INSERT_TEXT 的正确调用协议

键盘输入处理函数 `0x004C2290` 在输入字符 `.` 时调用编辑器虚函数表 `+0xE0`：

```asm
push 1                 ; 文本是键盘输入，启用语法解析
push offset text       ; 文本指针
push 1                 ; 当前编辑操作参数
push 0x0202006D        ; FN_INSERT_TEXT
call [edx+0xE0]
```

因此插件写入语句时必须传入 `parameter2=TRUE`。传 `FALSE` 会偏离 IDE 自己的键盘解析路径，可能导致文本写入了单元格但内部行索引、回读和刷新状态不同步。

### 2. FN_GET_PRG_TEXT

处理函数 `0x004C4CF0` 的分支 `0x004C4D64`：

- 负行号使用编辑器对象 `this+0x74` 的当前行；
- 负列号使用 `this+0x78` 的当前列；
- 先调用 `0x004918B0` 初始化文本缓冲；
- 真实单元格通过 `0x004B6400` 读取；
- 缓冲区为空时返回 `strlen+1`；
- 最后固定返回 `1`，越界也不表示读取成功。

### 3. FN_MOVE_CARET

光标移动相关函数 `0x004D0FE0`：

- 先通过 `0x004A08A0` 把逻辑行映射为实际网格行；
- `0x004A08A0` 对越界行返回 `-1`；
- 参数带有“按逻辑项移动”和“按实际行移动”的分支；
- 移动后仍必须读取当前行列确认，不能只相信 `NES_RUN_FUNC` 返回值。

### 4. 网格文本读取

`0x004B6400` 读取单元格时：

- 真实代码行类型为 `13` 时，会按代码项范围读取文本；
- 其他单元格走通用文本读取路径；
- 这解释了语句插入后立即读取可能暂时得到旧范围或旧行状态。

## 对 JadeDesigner 的影响

当前 `IdeEventRouter.cpp` 的 `FN_INSERT_TEXT` 调用已改为：

```cpp
InvokeIde(FN_INSERT_TEXT, PointerToDword(const_cast<char*>(text)), TRUE);
```

这比等待后重复提交更重要。后续验证应观察：

1. 第一次点击只新增一条订阅语句；
2. 第二次点击 `append_statement exists=1`，不再出现 `insert_row`；
3. 参数行不重复；
4. 光标只移动一次，不在参数/返回值列之间反复跳转。

## 暂未采用的路线

- `FN_INSERT_NEW_ARG` 的完整处理链还需要继续从分发器和网格命令表定位，当前没有足够证据替代已验证的参数兜底流程。
- 没有对 e5.95 原文件做 patch、写入或运行时修改。

## 追加分析：慢速与重复写入

### `FN_INSERT_TEXT` 键盘路径

`0x004C2290` 对字符 `.` 的处理是：

```asm
push 1
push offset text
push 1
push 0x0202006D
call [editor_vftable+0xE0]
```

插件必须复现最后一个 `1`，不能传 `FALSE`。这已经在 `1.6.32` 改正。

### `FN_GET_PRG_TEXT` 的时序特征

`0x004C4CF0` 的文本读取分支会先按当前编辑器的逻辑行/列解析代码项，再读取代码项范围。写入后如果编辑器尚未完成代码项范围重建，立即回读可能仍看到旧行或旧范围。插件当前每次失败会重新移动光标、重新执行多次扫描和再次插入，这会造成：

1. 单次点击耗时变长；
2. 日志显示 `verify=0`，但文本实际已经写入；
3. 下一次点击再次追加相同订阅。

因此下一步不应继续增加等待次数，而应将语句写入改成“提交一次 + 等待编辑器范围重建后单次验证”，失败时禁止自动重写。

### `FN_MOVE_CARET` 的开销

`0x004D0FE0` 先通过 `0x004A08A0` 将逻辑项转换为实际网格行，然后调用编辑器命令并触发滚动/刷新。当前插件在一次事件中多次切换程序集、子程序、参数列和返回值列，慢速主要由这些跨页激活和光标操作累积造成。

### 参数命令

在当前 IDA 数据库中，`0x0202000E` 没有作为普通立即数出现在代码段，说明 `FN_INSERT_NEW_ARG` 很可能通过菜单/命令表或间接分发，而不是一个直接 `push` 常量调用。需要继续从编辑器命令表、菜单资源和虚函数分发入口追踪，不能仅凭公开功能码猜调用参数。

## 追加分析：重复判重的实际代码缺陷

订阅语句通过 `WideToAnsi` 生成 GBK 字节，但此前使用 UTF-8 中文字面量直接判断：

```cpp
detectToken.find("JadeView.通讯.订阅")
```

该判断在 `/utf-8` 编译下与 GBK 字节不相等，导致订阅专用判重分支没有执行。当前已改为使用 `WideToAnsi(L"通讯.订阅")` 与 ASCII 前缀组合判断。
