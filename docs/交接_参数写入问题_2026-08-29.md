## 三、未解决问题：如何创建真正的 `.参数` 行

### 目标形态（参照真实工程 AI获客.e 的 ipc_获取二维码）

```e
.子程序 btn_import_accounts_被单击, 整数型
.参数 WinId, 整数型        ← 参数行紧跟子程序行，这是"参数表格区"的行
.参数 msg, 文本型

返回 (JadeView.文本.创建指针 ("ok"))
```

参数行是独立网格行，名称格 `VT_SUB_ARG_NAME`（=686 链 +50，约 740）、类型格 `VT_SUB_ARG_TYPE`。
**关键认知：`.参数` 文本写在语句区 ≠ 参数声明**（1.6.25 已实测：文本行留在语句区，是坏代码）。

### 已尝试并失败的方法（勿重试原样）

| 方法 | 结果 | 日志证据 |
| --- | --- | --- |
| `FN_INSERT_TEXT(".参数 ...")` 写进语句区 | 文本行留在语句区，不是参数 | 1.6.25 用户截图 |
| `FN_MOVE_CARET` 到空语句行 | IDE 把光标钳回上一内容行（want=7 got=6/0） | 1.6.22 |
| `FN_INSERT_NEW_ARG`（光标在子程序名称格） | **网格无任何变化**（page_dump 前后一致，行数不变） | 1.6.26/28：`new_arg_row=0` |
| 整页剪贴板替换（全选复制→改文本→粘贴） | **最近一次卡点，根因已定位，见下** | 1.6.28：`clipboard wide_empty` |

### ★ 最新根因（已定位，修复代码未应用——按用户要求停手）

1.6.28 的整页替换流程：菜单全选/复制 → `ReadClipboardPageCode(pageText)`（UTF-8，95 字节，成功）
→ 在 `.子程序 xxx` 行后插入 `paramLines` → `SetClipboardPageCode(modified)` → **失败 `clipboard wide_empty`**。

**根因**：`paramLines` 用 `WideToAnsi` 构造（**GBK 字节**），而 `pageText` 是 **UTF-8**。
`modified = pageText + paramLines` 是混合编码 → `SetClipboardPageCode` 内部
`Utf8ToWide`（带 `MB_ERR_INVALID_CHARS`）解析失败返回空 → 日志 `clipboard wide_empty` → 放弃。

**精确修复（改 `EnsureSubParams` 的 Attempt 2，约 60 行处）**：全程在宽字符域操作——

```cpp
// pageText(UTF-8) → wide；之后所有定位/插入都在 wide 域
std::wstring pageWide = Utf8ToWide(pageText);
// 行扫描改在 pageWide 上做（找 L".子程序 " 前缀 + 名称匹配），得到 wide 域 insertPos
std::wstring paramLinesWide;
for (const SubParamSpec& spec : params) {
    paramLinesWide += std::wstring(L".参数 ") + spec.name + L", " + spec.type + L"\r\n";
}
pageWide.insert(insertPosWide, paramLinesWide);
// 新增 SetClipboardPageCodeWide(const std::wstring&)：直接从 wide 设
// CF_UNICODETEXT + WideToAnsi(wide) 作 CF_TEXT（跳过 UTF-8 中转，见下）
```

并把 `SetClipboardPageCode` 拆出一个宽字符版本（1.6.28 已有宽松 ANSI 兜底、
OpenClipboard 重试 5 次、逐步 GetLastError 日志——保留这些）。

### 备选思路（若整页替换仍被 IDE 拒绝）

- `FN_INSERT_NEW`（FNST_MODIFY|1，“插入一个新当前单元”）/ `FN_INSERT_NEW_AT_NEXT`（|2）：
  光标落在子程序名称行时插入新行，**新行可能继承为参数行类型**（未验证，值得一试，成本低）。
- 插入新行后再用 `SET_AND_COMPILE_PRG_ITEM_TEXT` 填参数名格（VT_SUB_ARG_NAME 列）与类型格
  （VT_SUB_ARG_TYPE 列）——SET 单元格机制已验证可用（改名/返回值类型都是它）。
- 终极兜底：AutoLinker 的 RealPageCodeTool（内部文本包替换，特征码已在静态分析文档定位）。

## 四、网格事实（1.6.25-1.6.28 实测，写代码前必读）

- 程序集页：r0=表头（空），r1c0=程序集名（t=580）；子程序块=表头行(t=686,ti=1)+名称行(t=686,ti=0)，名称行 c1=返回值类型(t=687)、c2/c3=其他(t=690/688)；空语句行 t=851。
- `FN_GET_PRG_TEXT`/`NES_RUN_FUNC` **永远返回 TRUE**（越界也成功）：行存在性必须用
  `CellHasData()`（type≠0 || isTitle || reportedSize>1 || 文本非空）。
- `FN_MOVE_CARET` 到空语句行会被钳回上一内容行（无报错）——落点必须用
  `FN_GET_CARET_ROW_INDEX/COL_INDEX` 读回验证。
- **编码铁律**：任何进 IDE 的中文字符串必须是 宽字面量 → `WideToAnsi`（GBK）。
  直接写中文章语字面量是 UTF-8 字节，与 GBK 单元格比对/写入必败（1.6.20 事故）。
- 粘贴整页会忽略 `.程序集` 改名，但 `.子程序`/`.参数` 行生效——所以"不改名的整页替换"可用，"改名的整页替换"不可用。
- 剪贴板写回后要 `PumpMessagesFor(300)` 再验证；剪贴板守卫（ClipboardTextGuard）会恢复用户原剪贴板。
- 重入保护：Route 有原子锁；连续快速点击返回 busy。
